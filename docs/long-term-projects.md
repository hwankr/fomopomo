# 장기 과제와 선택적 과목 그룹

장기 과제는 이름만 입력해 시작한다. 처음부터 유형을 고를 필요가 없으며 다음 형태를 모두 지원한다.

- `코딩테스트`: 과목이나 세부 할 일 없이 타이머에서 바로 공부한다.
- `중간고사 → 시험 일정 확인`: 프로젝트에 직접 세부 할 일을 추가한다.
- `중간고사 → A과목 → 기출문제 풀기`: 프로젝트 안에서 **과목 추가**로 공통 과목을 선택한 뒤 필요한 세부 할 일을 추가한다.

프로젝트의 직접 세부 할 일과 과목 그룹을 함께 사용할 수 있다. 과목 그룹도 세부 할 일 없이 공부를 시작할 수 있다. 같은 프로젝트 안에서는 동일 과목을 한 번만 추가하지만, 다른 프로젝트에서는 같은 과목을 다시 사용할 수 있다. 기존 장기 과제는 별도 변환 없이 그대로 유지한다.

## 화면과 기록

- 계획 화면은 프로젝트 아래에 과목을 표시하고 과목별로 접고 펼친다. 프로젝트 진행률은 직접 세부 할 일과 모든 과목의 세부 할 일을 합산한다. 세부 할 일이 없는 과목은 완료한 항목으로 세지 않는다.
- 타이머 작업 목록에서도 같은 구조로 선택한다. 과목이나 세부 할 일을 선택하면 해당 과목으로 일간 할 일이 생성되며 `중간고사 › A과목` 경로를 함께 표시한다.
- 프로젝트 자체를 선택하면 기존처럼 프로젝트에 설정한 과목 또는 미분류로 기록한다. 과목 그룹을 선택하면 그 그룹의 과목을 사용한다.
- 이미 오늘 생성된 일간 할 일의 과목은 다시 선택해도 덮어쓰지 않는다. 과거 공부 기록의 과목은 명시적인 기록 수정 기능으로만 변경한다.
- 프로젝트 누적 시간은 프로젝트 직접 공부와 하위 과목 공부를 한 번씩 합산한다. 과목의 누적 시간에는 그 과목의 직접 공부와 세부 할 일 공부가 포함된다.
- 과목 그룹이나 세부 할 일을 삭제해도 이미 기록한 공부 시간과 과목은 남는다. 그룹을 삭제해도 당시 프로젝트에 쌓인 시간은 유지한다. 프로젝트 삭제 시 공부 기록 자체는 남기고 프로젝트 연결만 해제한다.

## 데이터 구조

`long_term_tasks.parent_task_id`가 없으면 프로젝트이고, 있으면 해당 프로젝트의 과목 그룹이다. 과목 그룹은 `subject_id`가 필수이며 동일 프로젝트·과목 조합은 유일하다. 부모는 동일 사용자의 최상위 프로젝트만 가능하다. `root_reference_id`는 트리거가 관리하는 내부 참조 열이며, CHECK와 외래 키로 순환 및 추가 중첩을 제한한다. 기존 실시간 갱신과 호환되도록 일반 열을 사용한다.

`study_sessions.long_term_task_id`는 공부 대상 과제, `long_term_project_id`는 기록 당시 프로젝트를 보존한다. 클라이언트가 전달한 값을 신뢰하지 않고 소유한 일간 할 일을 통해 두 값을 결정한다. `get_long_term_task_durations()`는 프로젝트에는 프로젝트별 합계, 과목 그룹에는 해당 과제별 합계를 반환한다. 화면에서 이 합계를 다시 더하지 않는다.

## 적용과 검증

먼저 `20261009122050_long_term_project_subject_groups.sql` 마이그레이션을 적용한 뒤 새 앱을 배포한다. 기존 과제의 ID와 구조를 보존하고, 기존 세션에는 새로운 프로젝트 참조만 보충한다. 시간·날짜·과목·배치 ID는 변경하지 않는다.

주요 회귀 검증은 다음 파일에 있다.

- `lib/__tests__/longTermTaskHierarchy.test.ts`
- `components/plan/__tests__/LongTermTasks.test.tsx`
- `components/plan/__tests__/TaskList.test.tsx`
- `components/__tests__/TaskSidebar.test.tsx`
- `components/timer/hooks/__tests__/useTasks.test.tsx`
- `supabase/tests/long_term_project_subject_groups.test.sql`
- `supabase/tests/long_term_project_subject_groups_backfill.test.sql`

SQL 테스트는 기존 `scripts/test-supabase-security.ps1`의 격리된 테스트 DB에서 실행하며, 실제 사용자 데이터를 테스트용으로 변경하지 않는다.

### 구현 검증 (2026-10-09)

- Vitest 54개 파일, 750개 테스트 통과. TypeScript, ESLint, 프로덕션 빌드 통과.
- 격리 PostgreSQL 18.6에서 관련 pgTAP 10개 파일, 376개 검증 통과(신규 58개 포함). 실제 두 연결의 동시 부모 변경·자식 추가도 양방향 검증했다. 운영 PostgreSQL 17에서의 실행 결과는 아니다.
- 실제 앱의 프로덕션 빌드와 로컬 PostgREST 16.4·PostgreSQL을 연결하여 프로젝트 생성, 직접 할 일과 A/B/C 과목 등록, 재조회, 빈 과목·세부 할 일 선택을 검증했다. 로그인과 사용자 설정만 격리된 응답으로 대체했고 관련 데이터 요청은 실제 로컬 DB에서 처리했다.
- 타이머에서 11초 기록을 저장해 과목·프로젝트 귀속 및 각각 11초 합계를 확인했다. 이후 화면에서 해당 과목을 삭제해도 세션의 과목과 프로젝트 합계가 유지됨을 확인했다.
- 390px·320px 계획 화면 및 320px 타이머 목록의 가로 넘침 없음. 관련 API 오류와 JavaScript 예외 없음. 로컬에서 제공하지 않는 기존 Vercel Analytics·Speed Insights 스크립트 두 건은 404였다.
- SQL lint·보안 advisor에서 변경 영역의 오류는 없었다. 기존 세션 배치 함수의 변수 경고와 테스트 fixture의 기존 feedback 정책 경고는 이 변경 범위에 포함하지 않았다.

이 검증은 운영 DB 마이그레이션과 배포를 포함하지 않는다.

### 운영 DB 적용 (2026-10-09)

사용자 승인에 따라 운영 `fomopomo` 프로젝트(`pqfozgiprhizwavfhjgv`, PostgreSQL 17.6)에 앱 푸시보다 먼저 적용했다.

| 소스 마이그레이션 | 운영 마이그레이션 버전 |
| --- | --- |
| `20261009122050_long_term_project_subject_groups.sql` | `20261009214841` |

소스 SHA256은 `56e32005f2e2bd73a17e527902f94c9d8484a99b8291784b03046da7876aafbb`다. 관리 API가 기록한 버전과 소스 파일의 시간이 다르므로, 위 대응표와 이름을 기준으로 확인하고 재적용하지 않는다.

적용 전후 읽기 전용 검증에서 기존 과제·세부 할 일·공부 기록의 개수 및 기존 열 체크섬이 일치했다. 공부 시간 합계도 동일하며 프로젝트 참조 보충과 기존 누적 시간의 불일치는 모두 0건이었다. 새 제약 5개와 인덱스 3개가 유효하고 두 트리거가 활성화돼 있다. 기존 소유자 RLS와 실시간 publication, 과제·세부 할 일의 `REPLICA IDENTITY FULL`도 유지했다.

`authenticated` 역할로 새 열과 누적 시간 RPC의 읽기를 확인했다. 세션 프로젝트 열의 직접 수정과 트리거 함수 직접 실행은 허용하지 않는다. Security Advisor의 항목·대상·개수는 적용 전후 동일했다. 기존의 의도된 [인증 사용자용 SECURITY DEFINER RPC 안내](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), `debug_logs` 정책 안내와 비밀번호 보호 경고는 그대로다.

# 고정 작업

플랜의 일일 작업 옆 핀 버튼으로 반복할 작업을 지정합니다. 같은 제목을 여러 과목에서 사용하거나 같은 과목에 같은 제목의 작업이 여러 개 있어도 각각 독립적으로 고정할 수 있습니다.

- 고정한 작업은 현재 날짜 또는 미래 날짜의 플랜을 열 때 날짜별로 한 번 생성됩니다. 날짜는 기기의 달력 날짜를 사용하며 과거 날짜를 열어도 새 고정 작업을 자동 추가하지 않습니다.
- 여러 탭에서 같은 날짜를 동시에 열어도 동일한 고정 작업은 하나의 일일 작업을 사용합니다. 기존 완료 상태와 순서는 유지됩니다.
- 고정된 일일 작업의 제목·과목을 바꾸면 해당 고정 템플릿에도 함께 저장됩니다. 저장 중 오류가 발생하면 둘 다 이전 값으로 유지됩니다. 다른 날짜에 이미 만들어진 작업과 공부 기록은 그대로 남습니다.
- 고정을 해제하면 해당 템플릿의 자동 추가만 종료됩니다. 이미 만들어진 일일 작업·공부 시간·과목 기록은 삭제하지 않습니다. 나중에 다시 고정하면 새로운 템플릿으로 시작합니다.

## 배포 및 기존 데이터

UI 배포 전에 `supabase/migrations/20261003050311_pinned_task_identity.sql`을 적용해야 합니다. 마이그레이션은 일일 작업의 `source_pinned_task_id`, 소유자를 함께 검증하는 외래 키, 템플릿·날짜 유니크 인덱스와 다음 RPC를 추가합니다.

- `pin_daily_task`: 일일 작업을 잠그고 템플릿 생성과 연결을 같은 트랜잭션에서 처리합니다.
- `materialize_pinned_tasks`: 요청한 사용자와 인증 사용자가 같은지 검증하고 고정 템플릿의 일일 작업을 멱등적으로 생성합니다.
- `update_daily_task_with_pin`: 일일 작업과 현재 연결된 고정 템플릿의 편집을 원자적으로 저장합니다.

세 RPC 모두 `SECURITY INVOKER`이며 기존 RLS를 우회하지 않습니다. 익명 호출은 허용하지 않습니다. 고정 템플릿 삭제 시 외래 키는 `source_pinned_task_id`만 비우고 작업 소유자를 보존합니다.

기존 데이터는 **사용자·제목·과목이 정확히 일치**하고 해당 날짜에 작업과 템플릿이 각각 하나인 경우에만 연결합니다. 미분류 과목도 같은 조건으로 비교합니다. 같은 조건의 작업이나 템플릿이 여러 개이거나 장기 과제·세부 작업에서 생성된 행은 연결을 추측하지 않습니다. 기존 행을 삭제하거나 공부 기록을 다시 분류하지 않습니다.

연결을 결정할 수 없는 기존 작업은 일반 작업으로 남습니다. 해당 템플릿의 현재·미래 날짜를 처음 열면 별도의 연결된 작업이 생길 수 있으므로, 사용자가 내용을 확인한 뒤 불필요한 템플릿의 고정을 해제하고 기존 작업은 필요에 따라 정리할 수 있습니다.

## 검증

`components/plan/__tests__/TaskList.test.tsx`는 같은 제목의 독립 작업, 동시 조회 결과, 고정 해제·편집, 계정·날짜 전환과 실패 복구를 검증합니다. DB 제약과 권한·기록 보존은 `supabase/tests/pinned_task_identity.test.sql`, 실제 마이그레이션의 기존 데이터 연결은 `supabase/tests/pinned_task_identity_backfill.test.sql`에서 검증합니다. 마이그레이션 재실행 테스트는 트랜잭션을 롤백하는 독립적인 테스트 DB에서 실행해야 합니다.
